## 2. Один раз подготовьте PowerShell

Откройте PowerShell в **корне своего проекта HOM_project_new**. Не в папке агента.
Команды в блоках `powershell` вводятся в PowerShell; тексты заданий передаются
модели автоматически запускателем.

```powershell
Get-Location
Test-Path .\AGENTS.md
Test-Path .\src\quick_fit.py
Test-Path .\ollama_kit\run_goose.py
```

Три последних ответа должны быть `True`. Затем:

```powershell
$project = (Get-Location).Path
$kit = Join-Path $project "ollama_kit"
python -m venv .venv-course
$py = Join-Path $project ".venv-course\Scripts\python.exe"
& $py -m pip install --upgrade pip
& $py -m pip install torch --index-url https://download.pytorch.org/whl/cpu
& $py -m pip install -r "$kit\requirements.txt"
```

Используется отдельное окружение проекта: установка курса не меняется.
CPU-версия PyTorch нужна поисковому ноутбуку; Ollama использует свою GPU-среду.
Установка библиотек и первого кодировщика может занять время.
Не продолжайте, если pip завершился ошибкой.

Проверьте `.gitignore`: добавьте строки `.venv-course/`, `__pycache__/`, `.env`,
`.env.*`, если их ещё нет. Не добавляйте всю виртуальную среду в репозиторий.

Проверьте Ollama:

```powershell
ollama signin
ollama run gemma4:31b-cloud
```

Спросите «Ответь одним словом: работает?», затем `/bye`.
Для сравнения трёх моделей в ноутбуке недели 3 понадобится ещё маленькая модель:

```powershell
ollama pull qwen3:4b
ollama list
```

`qwen3:8b` у вас уже скачана. Для облачной модели не скачиваются её полные веса.
Если облако недоступно/лимит исчерпан, сохраните ошибку и переключите отдельные
простые задачи на локальную модель. Не записывайте неудавшийся опыт как успешный.

### Как устроен каждый следующий запуск

Запускатель сам передаёт соответствующий файл из `prompts/`, устанавливает
`approve`, рабочую папку и контекст (32 768 для облака; 8192 для локальной модели).
Он запускает одну задачу и остаётся в диалоге для уточнений/приёмки. После `/exit`
сохраняет в `logs/<имя-сессии>/`:

- `request.txt` — фактически переданный запрос;
- `run.json` — модель, провайдер, время, рабочая папка, запрошенный контекст;
- `session.md` и `session.json` — экспорты реального разговора, если экспорт доступен;
- для research — `research_calls.jsonl` с настоящими аргументами и ответами MCP.

`goose_process_exit_code: 0` означает нормальный выход процесса, **не зачёт задания**.
`task_result` и `human_review` намеренно остаются неподтверждёнными: итоги фиксируются
отдельной проверкой и вашим решением. Хеши data/checks/ontology обнаруживают изменения
после сессии, но не являются защитой файловой системы. Защита на уровне вызова —
ваше отклонение недопустимых команд в режиме approve.

Если экспорт не сработал, сохранится его ошибка. Не перезапускайте всю научную
задачу из-за экспорта: посмотрите `info`, `session list` и экспортируйте существующую
сессию. Если достигнут предел ходов, сначала оцените прогресс; он не является
универсальной гарантией против всех повторов и фоновых обращений модели.

При новой PowerShell-сессии восстановите только переменные:

```powershell

$project = (Get-Location).Path
$kit = Join-Path $project "ollama_kit"

```

вашей задаче и почему выдачи отличаются. Оставленные «…» не считаются разбором.

## 14. Если что-то ломается

| Симптом | Следующий шаг |
|---|---|
| Модель просит URL для AGENTS.md | Проверьте startup-список расширений; developer должен быть подключён. Попросите shell выполнить Python pathlib чтение. При повторе сохраните журнал и остановитесь. |
| Ollama connection refused | Запустите приложение Ollama; локальный адрес должен отвечать. Не запускайте второй сервер поверх уже работающего. |
| 401/вход в Ollama | `ollama signin`, затем короткий `ollama run ...:cloud`. |
| Облачный лимит/429 | Сохраните ошибку; местные проверки и личные сверки доступны. Простую задачу можно повторить отдельно на qwen3:8b, отметив смену модели. |
| Не хватает памяти GPU | Закройте лишние программы; `ollama ps` покажет модель. Для текущего этапа можно использовать облако. Не увеличивайте локальный контекст до 32k вслепую. |
| Notebook просит Yandex key | Открыт старый файл. Нужен `ollama_kit/week3/agent_loop_ollama.ipynb`. |
| Notebook не находит numpy/mcp | Проверьте ядро и путь sys.executable; установите requirements в то же окружение. |
| Файл не найден | Проверьте рабочую папку и `--project`, не переписывайте данные. |
| Goose утверждает успех, но проверки нет | Выполните независимую проверку; слова модели не являются результатом команды. |
| Повторяет одинаковые действия | Ctrl+C; сохраните журнал; разберите ошибку перед новой попыткой. |
| Проверка графа требует недостающую связь | Исправьте граф по существующей онтологии, не ослабляйте проверку. |
