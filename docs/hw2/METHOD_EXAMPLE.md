# Методика проверки: растворимость соединений в воде по дескрипторам

Заполненный пример шаблона `METHOD_TEMPLATE.md` для учебного проекта. Числа — из прогона
2026-10-18 (ноутбук `experiment_lab.ipynb`, один поток).

## 0. Паспорт

| Поле | Значение |
|---|---|
| Задача | прогноз logS (десятичный логарифм растворимости в моль/л) по 17 дескрипторам структуры |
| Дисциплина | химия |
| Ветка верификатора | тесты на свойствах и проверка данных |
| Дата записи методики | 2026-10-18, до первого прогона |
| Метка git | `exp-baseline` |

## 1. Замысел

- **Вопрос:** насколько точно 17 дескрипторов предсказывают logS для соединений, которых не
  было в обучении, и какой вклад вносят признаки липофильности MolLogP и MolMR.
- **Гипотеза:** без MolLogP ошибка растёт; на случайном разбиении ошибка ниже, чем на
  разбиении по кластерам соединений.
- **Что считается ответом:** RMSE на разбиении авторов набора с бутстреп-интервалом; для
  абляции — разность RMSE с интервалом и поправкой на множественные сравнения.

## 2. Постановка

| Что | Значение |
|---|---|
| Что меняем (факторы и уровни) | скорость обучения 0,03 / 0,1 / 0,3; число листьев 7 / 31; набор признаков (все, без MolLogP, без MolMR, без обоих) |
| Что фиксируем | модель `HistGradientBoostingRegressor`, 300 итераций без ранней остановки, версию данных |
| Что измеряем, в каких единицах | RMSE в единицах logS; дополнительно MAE и R² |
| Базовая линия | предсказание средним по обучающей части |

## 3. Данные

| Что | Значение |
|---|---|
| Источник | AqSolDB (Sorkun, Khetan, Er, Sci. Data, 2019), зеркало `maomlab/AqSolDB` на Hugging Face |
| Версия | ревизия `c95582978d7978519f123fe6eea2574b5fce3659`, закреплена в `src/aqsol/data.py` |
| Лицензия | MIT |
| Объём | 9 982 соединения: 7 488 в обучении, 2 494 в проверке |
| Разбиение | для вывода о новых соединениях — разбиение авторов (крупный кластер в обучении, малые в проверке); для перебора — случайное 75/25, его задаёт seed |

**Договор о схеме данных** — `src/aqsol/contract.py`, функция `check_data`:

| Правило | Как проверяется | Код нарушения |
|---|---|---|
| столбцы на месте, признаки — числа без пропусков | `check_schema` | `missing_columns`, `not_numeric`, `missing_values` |
| logS в [−15; 3], молярная масса больше нуля | `check_schema` | `target_range`, `molwt_range` |
| счётчики целые и не отрицательные | `check_schema` | `counts` |
| тождества: RingCount = ароматические + алифатические кольца; насыщенные ≤ алифатических; гетероатомы ≤ тяжёлых атомов | `check_identities` | `ring_sum`, `saturated_rings`, `heteroatoms` |
| ключ InChIKey уникален, одна запись SMILES — одно соединение | `check_keys` | `duplicate_key`, `smiles_collision` |
| соединения не повторяются в двух частях разбиения | `check_split` | `split_overlap` |

**Известные нарушения.** `smiles_collision`: в зеркале у записей SMILES срезаны противоионы,
148 записей описывают разные соединения (367 строк), например PdCl₂ и PdO записаны как
`[Pd+2]`. Ключ соединения — InChIKey; SMILES не используется ни как ключ, ни как признак.

## 4. Код и окружение

- Где код: `src/aqsol/` — вычисления в чистых функциях (`contract.py`, `model.py`,
  `experiment.py`, `stats.py`, `units.py`), чтение и запись — в `data.py` и `logbook.py`.
- Команда запуска: `python run_experiment.py dry | smoke | sweep | full`.
- Окружение: Python 3.11, пакеты из `requirements.txt`; `OMP_NUM_THREADS=1` (результат от
  числа потоков не зависит, проверено сравнением журналов).
- Значения seed: 0–4; seed задаёт случайное разбиение и модель.

## 5. Верификатор

- **Что проверяет:** договор о схеме на настоящих данных; 13 свойств кода — обратимость
  перевода единиц, независимость от единицы массы, отказ складывать несовместимые
  размерности, разбиение без потерь и повторов, тождества колец, антисимметричность парной
  разности, интервал содержит среднее, поправка Холма не уменьшает p-значения, RMSE ≥ 0 и
  равна нулю на точном прогнозе, имя прогона зависит только от конфигурации, размер сетки;
  журнал TensorBoard содержит кривую и гиперпараметры.
- **Команда:** `python -m pytest checks tests -q` (15 проверок).
- **Где лежит:** `checks/`, закрыт для агента от записи.
- **Чего не проверяет:** правильность самих измерений растворимости; химическую
  осмысленность дескрипторов; то, что разбиение авторов отражает ваш круг соединений.

| Шаг | Команда | Условие перехода к следующему шагу | Время |
|---|---|---|---|
| Пробный прогон | `python run_experiment.py dry` | договор выполнен, кроме `smiles_collision`; план из 30 прогонов, имена не повторяются | 0,02 с |

## 7. Правило принятия (записано до запуска)

1. **Метрика и единицы:** RMSE на проверочной части, единицы logS.
2. **Повторы:** 5 повторов, seed 0–4, общие для сравниваемых конфигураций.
3. **Сравнение:** на случайных разбиениях — парное на общих seed: средняя разность, 95-процентный
   интервал, парный критерий Стьюдента, уровень значимости 0,05, поправка Холма при
   нескольких сравнениях. На разбиении авторов — один прогон каждого варианта (модель
   детерминирована) и бутстреп-интервал разности RMSE по соединениям проверочной части.
4. **Практический порог:** 0,13 log-единицы — медиана стандартного отклонения повторных
   измерений logS у 2 236 соединений набора.
5. **Выбор варианта:** по среднему по повторам; лучший отдельный seed выбор не определяет.
6. **Разбиение для вывода:** вывод о новых соединениях — только на разбиении авторов.
7. **Остановка:** шаг дважды подряд не проходит по одной причине — остановиться и разобрать
   причину.

## 8. Бюджет

- Время счёта: весь путь — меньше минуты в один поток.
- Токены агента: не больше 1 млн на одно изменение OpenSpec (на репетиции полный цикл
  изменения «абляция» занял 3,5 млн — изменения нужно делать меньше).

## 10. Ограничения

- Метрика усреднена по всем соединениям: на неорганике и солях ошибка выше средней.
- Вывод о вкладе признаков зависит от разбиения: на случайном разбиении MolMR без MolLogP
  почти ничего не добавляет (+0,005, p-значение 0,39 с поправкой Холма), на разбиении авторов
  его удаление ухудшает RMSE на 0,084 (интервал 0,065–0,103).
- Различия на случайных разбиениях меньше порога шума 0,13: статистически значимы и
  практически малы.
- Порог шума оценён по соединениям с повторными измерениями; для остальных он неизвестен.
