## Формальное направление: что видит проверяющий

Маленькая теорема без Mathlib (проверено в Lean 4.31 и 4.35): сумма первых `n` нечётных чисел
равна `n²`.

```lean
/-- Сумма первых n нечётных чисел: 1 + 3 + … + (2n − 1). -/
def sumOdd : Nat → Nat
  | 0 => 0
  | n + 1 => sumOdd n + (2 * n + 1)

theorem sumOdd_eq (n : Nat) : sumOdd n = n * n := by
  induction n with
  | zero => rfl
  | succ k ih =>
    have square : (k + 1) * (k + 1) = k * k + 2 * k + 1 := by
      rw [Nat.add_mul, Nat.mul_add, Nat.mul_one, Nat.one_mul]
      omega
    simp only [sumOdd, ih]
    omega

theorem sumOdd_draft (n : Nat) : sumOdd n = n * n := by
  sorry

#print axioms sumOdd_eq
#print axioms sumOdd_draft
```

Вывод:

```
Odd.lean:16:8: warning: declaration uses `sorry`
'sumOdd_eq' depends on axioms: [propext, Quot.sound]
'sumOdd_draft' depends on axioms: [sorryAx]
```

- Файл с `sorry` собирается с кодом 0: `sorry` даёт только предупреждение. Поэтому в пакет
  входит вывод `#print axioms` — по нему видно, закрыто ли доказательство.
- `propext` и `Quot.sound` — стандартные аксиомы ядра Lean (их используют тактики `simp` и
  `omega`); с Mathlib к ним часто добавляется `Classical.choice`. Работа не принимается
  только при `sorryAx`.
- Для работы на своей задаче теорема должна формулировать свойство, нужное задаче; пример
  выше показывает только форму сдачи.

Дерево подцелей для этого примера:

```
sumOdd n = n * n
├── база: sumOdd 0 = 0 * 0                       — rfl, 1 попытка
└── шаг: sumOdd k = k * k → sumOdd (k+1) = (k+1)*(k+1)
    ├── раскрыть квадрат (k+1)*(k+1)             — rw + omega, 2 попытки
    └── свести к линейной арифметике              — simp only + omega, 1 попытка
```

Журнал попыток: первая попытка шага — `rw [sumOdd, ih, Nat.succ_mul, Nat.mul_succ]; omega` —
не прошла: `omega` не связал произведения `(k + 1) * k` и `k * k`. Вторая — отдельная лемма о
квадрате, после которой произведения остаются в одном виде, и `omega` закрывает цель.
